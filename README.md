# 每日自动打卡 App

这是一个个人自用的 Android 本地 App。每天第一次打开时自动打卡，当天重复打开不会新增记录。数据只保存在手机中，不需要登录、网络、服务器或后台常驻。

当前版本：**2.1**

## V2.1 UI 优化

- 全局品牌主色统一为 `#2D6A4F`
- 页面背景改为暖灰白，卡片使用白色和极细边框
- 卡片圆角统一为 12dp，主状态卡使用 14dp
- 字体权重只使用 400 和 600
- 首页改为绿色渐变状态卡，并加入当月日期点阵
- 月历增加顶部统计摘要、绿色打卡状态和图例
- 列表增加月度环形进度卡与紧凑记录卡

## V2 功能

- 打开 App 自动记录当天第一次打开时间
- 每天最多保存一条记录
- 首页显示今天日期和星期
- 区分“今天打卡成功”和“今天已经打过卡”
- 显示当前连续、历史最长、本月打卡和累计打卡天数
- 显示本月截至今天的打卡率
- 月历用绿色日期标记已打卡日，并支持前后翻月
- 历史记录支持“月历 / 列表”切换
- 列表按月份分组，并显示日期、星期和打卡时间
- Room 数据库本地持久化
- 不申请网络、定位、通知或后台权限
- GitHub Actions 自动测试并生成 debug APK

V2 没有修改数据库结构。直接覆盖安装 V1 APK 时，原有打卡记录会继续保留。请不要先卸载 V1，因为卸载会清除本地数据。

## 不需要 Android Studio

你不需要安装 Android Studio、Android SDK，也不需要在电脑上运行 Gradle。项目包含 Gradle Wrapper，并由 GitHub Actions 云端完成测试和 APK 构建。

## 上传 V2 文件到 GitHub

如果继续使用 GitHub 网页：

1. 打开 `wangxiuchen/DailyCheckIn` 仓库。
2. 进入 `Code` 页面。
3. 点击 `Add file` > `Upload files`。
4. 上传本项目中发生变化的文件，保持原有目录结构。
5. 确认新增的 `MonthCalendar.kt`、`MonthCalendarTest.kt` 和 `ic_launcher.xml` 也已上传。
6. 提交说明填写 `Upgrade to version 2.0`。
7. 点击 `Commit changes`。

网页逐个更新目录容易漏文件。最稳妥的方式是上传完整项目内容并覆盖同名文件，但不要上传本地隐藏的 `.git` 文件夹。

## GitHub Actions 构建

提交到 `main` 分支后，`Build Android APK` 会自动运行：

1. 打开仓库顶部的 `Actions`。
2. 左侧选择 `Build Android APK`。
3. 等待最新任务从黄色圆圈变成绿色对勾。
4. 如果没有自动运行，点击 `Run workflow`，分支选择 `main`。

工作流会依次运行：

```text
./gradlew testDebugUnitTest
./gradlew assembleDebug
```

## 下载和安装 V2

1. 点击最新一次成功的 Actions 构建。
2. 在页面底部找到 `Artifacts`。
3. 下载 `daily-check-in-debug-apk`。
4. 解压 zip，找到 `app-debug.apk`。
5. 把 APK 通过微信、QQ、数据线、网盘或邮件发送到小米 15。
6. 在手机上点击 APK。
7. 按系统提示允许当前文件来源安装未知应用。
8. 直接安装并覆盖 V1，不要先卸载。

如果系统提示安全风险，请确认 APK 来自你自己的 GitHub Actions 构建后继续。

## V2 验收

安装后检查：

1. 首页显示今天日期、星期和打卡时间。
2. 首次打开显示“今天打卡成功”。
3. 当天再次打开显示“今天已经打过卡”，打卡时间不变。
4. 首页显示当前连续、历史最长、本月和累计数据。
5. 本月打卡率按本月截至今天计算。
6. 历史页默认显示月历，今天应为绿色。
7. 可以切换上个月和下个月。
8. 切换到列表后，记录按月份分组并按日期倒序显示。
9. V1 已有记录仍然存在。
10. 飞行模式下 App 仍能正常使用。

## 常见问题

### Actions 构建失败

打开失败任务，点击红色步骤，复制第一段关键报错或截图发给 Codex 继续修复。

### 安装时提示应用已存在

正常情况下可以覆盖安装。确保新旧 APK 都来自同一个项目的 GitHub Actions 构建。不要卸载旧版，否则本地记录会被删除。

### 月历中以前的日期没有变绿

月历只会标记数据库中真实存在的打卡记录。V1 使用期间没有打开 App 的日期不会自动补签。

### 本月打卡率为什么不是按整月计算

V2 按“本月已过去的天数（包含今天）”计算，未来日期不会提前降低打卡率。

### App 会在后台自动打卡吗

不会。只有打开或回到 App 时才会检查当天记录，没有后台任务和定时打卡。
